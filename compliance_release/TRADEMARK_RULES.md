# 商标与品牌合规规范（发布形态合规 · Round 2 补齐）

> 日期：2026-10-10。依据：ADR-C1（闭源最严姿态）§1 特异性命名零容忍 +
> 用户 6 项改造清单第 ⑥ 项。适用范围：产品全部分发形态（二进制、安装包、
> 仓库、文档、官网、应用商店元数据）。

## 1. 我方命名域

- 产品/工程命名一律使用自研命名域：`mdcore` / `mdshell` / `mdc-*` 前缀
  （shell-native 事件名已在 RC 轮统一为 `mdc-inject*`）。
- 可执行文件名、包名、协议 scheme（`mdcore://app`）、User-Agent、
  窗口类名、进程名不得含四参考对象的任何品牌词——该约束已由合规门禁
  `scan.sh` 品牌词扫描恒定保证（产品内容零命中，见 RC-R 报告 §5）。
- 正式发布名（对外商品名）尚待定；定名前须完成 §4 检索流程，并复跑
  品牌词门禁确认零冲突。

## 2. 对四参考对象商标的禁止事项

Typora、MarkText/muya、Obsidian、Zed（含 delta 产品名及其图形标记，
下称"对象标记"）均为各自权利人的商标/服务标记：

1. **不得在产品名、仓库名、可执行名、图标、UI 文案中使用对象标记**，
   或其足以引起混淆的近似变体（音译、形近、含义绑定，如 "TyporaX"、
   "Obsidia" 类构造）。
2. **不得暗示背书或关联**：不得使用 "官方"、"authorized"、对象 logo、
   配色-字形组合使公众误认为关联或认可。
3. **兼容性表述边界**：
   - 允许（描述性正当使用）：兼容 Markdown（CommonMark/GFM 规范词）、
     "导入 .md 文件"、"适用于标准 Markdown"。
   - 禁止（商标性使用）："Typora 兼容"、"Obsidian 插件生态兼容"、
     "Zed 内核" 等未经许可的指向性表述。
4. **对比性陈述**：性能/功能对比如提及对象名，限于客观、可验证、
   非贬损的事实陈述，并明确"仅为第三方商标，无关联"（广告法与商标
   合理使用双重口径）；营销物料中的对比默认改为匿名化表述
   （"主流 Markdown 编辑器"）。
5. **元数据与法律文本**：发行物法律声明区加入通用归属句：
   "Typora、MarkText、Obsidian、Zed 等为各自权利人的商标，本项目与其
   无关联、未获其背书。"（防 Attribution 混淆风险的最小成本做法。）

## 3. 我方标记的使用规范（发布前填充）

- [ ] 确定商品名 + 域名 + 仓库组织名三件套一致性；
- [ ] logo 使用清单：主标/单色标/favicon/安装图标，最小尺寸与留白；
- [ ] README 与"关于"页的版权 + 许可声明（闭源 EULA 待起草，挂 ADR-C1）；
- [ ] 应用商店元数据（名称、副标题、关键词）不含对象标记与通用词堆砌；
- [ ] `mdcore://` scheme 与桌面入口名在安装器中的注册一致性。

## 4. 定名前检索流程（强制门）

1. 中国商标网（第 9 类计算机软件、第 42 类 SaaS）近似检索；
2. WIPO Global Brand Database + 马德里体系初筛；
3. 目标发行市场 common-law 使用检索（编辑器/文本处理品类）；
4. 域名与主流平台账号可用性；
5. 检索记录归档至本目录（`trademark_search_<date>.md`），作为
   善意（bona fide）采用证据链的一环。

## 5. 与合规门禁的挂接

- 品牌词维度已由 `scan.sh`（RC-R 报告 §5 口径）覆盖：产品内容对
  typora/obsidian/muya/zed/gpui 词边界零命中，`Delta` 裸词仅数学语义。
- 本规范新增的发布形态检查项（§2.3/2.5、§3、§4）在**发行态构建**
  （R22-f 双 profile 的 release profile）打包流程中执行人工核查单，
  核查记录随发行归档。
