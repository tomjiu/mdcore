# #234：.doc 旧格式识别与错误归因（2026-11-06，R11·P2 / 研究仓 batch2 · ai-bid-research #270 仓外面）

**背景**：异源 .doc（OLE2 复合文档）改名 .docx 后，zip 读入口报
「container corrupt: Could not find EOCD」——误导用户以为文件损坏；
实为容器层面可识别的旧格式。与 ai-bid-research #270（仓外侧已由
PR #282 收口）为同一问题的仓内外两面，本件收引擎侧。

**实现**（分支 fix/doc-ole2-detection）：
- `io.rs`：`OLE2_CFB_MAGIC` 常量 + `is_ole2()` 探测（不足 8 字节
  false——短输入不劫持）+ `ReadError::LegacyOfficeFormat { expect }`
  专用变体（Display = 识别结论 + 可操作指引：Word「另存为 .docx」/
  soffice --headless --convert-to docx）；
- `docx.rs::read_bytes_gated`（读面 path/bytes 四入口漏斗）+
  `docx_edit.rs::open_with_policy`（编辑面）魔数前置——先于 zip 装载，
  不再触达 EOCD 误报路径；
- wasm 错误码：docx 面 `docx_legacy_format`（模块文档表同步）；xlsx
  面防御性臂 `container_legacy_format`（xlsx 读入口未接线 OLE2 嗅探
  ——.xls 改名 .xlsx 同构问题守边界登记，循研究仓 #270 侧同边界
  先例）；
- `tests/docx_ole2_reject.rs`：4 锁——专用错误 + 指引 + 不误报
  EOCD（8B/512B/539KB 三尺寸，539KB = 研究仓真实语料同量级）/ 短
  输入不劫持 + 垃圾字节仍 ContainerCorrupt / 编辑面同防御 / 合法档
  写读往返零扰动正控。

**验证面**：本地（Linux，1.99.0）——office-io **360 ok / 0 failed**
（含新增 4）；mdcore-wasm 148 ok / 0 failed（含新映射测试断言）；
workspace（exclude mdshell-native）148 组全绿；wasm32 check 过；
fmt 0 diff；clippy 零新警告（mdcore-wasm 既有基线 5+1 恒等）；scan
自增面零命中（基线 A3 两行既有红，修复在 #237）；CI 三门禁。

**登记边界**：全量 .doc 解析（OLE2 内部结构）不在本项（issue 明示
缓议）；.xls 改名 .xlsx 同构问题登记不修（issue 只点名 .doc）；合成
CFB 载荷锁魔数面——真实 .doc 语料的容器级验证在研究仓 #270 侧已做。
