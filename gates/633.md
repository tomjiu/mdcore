## B1：unipoll 主循环落地（2026-11-10，新站 issue #49 工作线 B / Agent-2ddj）

**基线**：新站 main `2e9d233`（= 旧首版 + 平台迁移文档提交）。**增量合入**
（不整树覆盖，按 #49 派工单）：保留首版全部模块组织（abi/protocol/
runtime/profile/smoke/client/worker + 写线程 + fake 模式 + no_kernel_loop
+ 环境卫生 + 退出纪律），仅把 worker 主循环从「阻塞 stdin 直调」改为
unipoll 集成：

| 改动 | 文件 | 内容 |
|---|---|---|
| unipoll 主循环 | `worker.rs` | `request_loop` → `unipoll_loop`：reader 线程（协议流→channel）+ 主线程进 kit `runLoop`（poll 回调里 JSON 解析+分发+应答 = 内核主循环上下文同步执行；wake 回调经共享通道叫醒 poll）。`runLoop` 槽位纳入 bind_kernel nSize 守卫（缺槽 = boot-failed 明确报错，不回退直调——直调模式有异步事件黑洞，产品不可用，宁可明确失败） |
| fd 0 抢救 | `worker.rs` | `steal_stdin_fd`：dup 保管道、fd 0 换 /dev/null（unix dup/dup2，win `_dup/_dup2`），防 LO 内嵌组件（python 等）抢读协议流撕碎帧（本仓 Linux 实测复现：连续 post_key 中途偶发挂起）；任何 LO 初始化之前执行；no_kernel_loop 同步改用抢救 fd（fd 0 已不可用） |
| unipoll env | `worker.rs` + `client.rs` | `SAL_LOK_OPTIONS=unipoll` 双侧幂等设置（worker env_hygiene 在 hook_2 前自设；宿主 spawn 也设）。**配套铁律**：只设 env 不进 runLoop 会 SIGSEGV（实测 rc=-11）——两者必须同时存在 |
| 槽位 offset | `abi.rs` | `kit_offsets::RUN_LOOP`（`run_loop` 字段首版已声明，B1 补 offset 常量入守卫表） |

**事件消费证明（B1 验收核心——"证明实际键鼠/UNO 事件被消费"）**：
unipoll 化的机制依据 = LO 的 `postKeyEvent/postMouseEvent/postUnoCommand`
均 `postKeyEventAsync` → `Application::PostUserEvent` 入队（unotxdoc.cxx
:4015-4018），消费依赖主循环被泵；直调模型下 `lo_startmain` 线程可整段
沉睡（wchan=futex 实证，CPU 0.05s/6s）→ 编辑静默丢失（smoke 复跑 4 连败
实录）。unipoll + runLoop 下 `postEventAsync` 直调 `LOKPostAsyncEvent`
（lokhelper.cxx:1283-1290），同步确定。**实测**：smoke 26 步连跑
**3/3 全绿**（每次 ~16.8s）——键入替换正文（dirty=true）、
INVALIDATE_TILES 回调到达、saveAs 产物含编辑文本（6596B）、拒写保脏位、
源文件 hash 不变、双 worker 并行 + worker2 重开校验全过。

**pending 竞态核对（B1 派工项）**：首版 client `request_with_timeout`
已是**先登记后写**（`p.insert(id, tx)` → 序列化 → 写帧；写失败/超限
remove）——2ddj 线在独立实现里修过的竞态（先写后登记 → mock 微秒级
响应被丢 → 假超时）在首版代码上**不存在**，无需改动（核对结论，非跳过）。

**实现**（分支 feat/633-lok-worker，独立 worktree，基于 main `cbcfcdb`）：

新 crate `crates/lok`（mdc-lok，三方依赖仅 serde_json workspace 单源；
对 mdcore 零 path 依赖——三域纪律：LOK = Office 域外部运行时）：

- **ABI 面**（`abi.rs`）：按 pin commit `0d51fdc` 的
  `LibreOfficeKit.h` 手写 `#[repr(C)]` 类结构，**绑定止于 Doc#18 /
  Kit#12**（两版同序段；LO 26.x 曾在 Doc#19 前插入成员——ElyOffice slot

  `std::mem::offset_of` + 运行时 `nSize`）逐成员守卫。
- **运行时发现**（`runtime.rs`）：`MDC_LOK_HOME`/`MDC_LOK_LIB` → 部署位
  （exe 旁 `LOK/`、仓 `bin/`）→ 平台常见位；内核库选择序 = 官方
  `LibreOfficeKitInit.h` 的 `lok_dlopen`（sofficeapp >1000B 优先，否则
  merged）。**宿主进程永不 dlopen 内核**（隔离铁律）；发现期计算内核

- **单文档 worker**（`worker.rs` + `mdc-lok-worker` bin）：JSON-lines

  统计）不走帧；回调经队列由写线程单点转发；退出一律 `_exit`（跳过 LO

- **宿主客户端**（`client.rs`）：spawn/请求/事件路由/超时/死亡扩散/

**实测踩坑实录**（都已修/规避，防复发）：

1. **hook_2 的 install_path 是 program 目录**，不是安装根——头文件注释
   与实现不符（`lo_initialize`：`BRAND_BASE_DIR=install/..`、
   `setIniFilename(install+"/sofficerc")`）。传安装根 →
   `theDefaultProvider` bootstrap 异常 → 段错误（C 探针 + 纯 C++
   对照复现链）。
2. **`Option<CString>.map(|c| c.as_ptr())` 悬垂指针**：map 表达式结束
   CString 即 drop，LO 读到垃圾 JSON → boost ptree 抛 C++ 异常穿过
   Rust 帧 → `Rust cannot catch foreign exceptions` abort（op_load/
   op_uno/op_init_rendering/op_save_as 四处全改 `as_ref().map().`
   生命周期延展）。
3. **LO 25.2 销毁带 doc 级回调的文档 → 内核 teardown 路径 SalAbort
   直退**（C++ 对照实验：无 doc 回调 destroy 干净；setTextSelection
   RESET 预清理无效）→ 一次性 worker 的 close/shutdown **跳过 destroy**
   （`destroy_skipped: true`，内存由进程退出回收，落盘只依赖 saveAs）。
4. **mime 必须用 `text/plain;charset=utf-8`**（裸 `text/plain` 不是
   transferable flavor，返回空）。
5. **Writer 表格内首个 SelectAll 只选单元格**（1 次=单元格/2 次=表/
   3 次才全文）→ `select_all_full_text` 重试到含全部期望标记。
