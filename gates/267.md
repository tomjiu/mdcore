**背景**：#267 派单时正文按「只读 styleId 名字，不解析继承链」的现状
描述，但 s1-t1（`4304ca2`，2026-10-31 已合）已先行交付 StyleTree 基座：
`StyleRef` 的 basedOn/next/link/is_default/qFormat/uiPriority 全字段解析、

铺底 → 链逐层 Some 覆盖）与写面 define_style/styled_paragraph。本条为
**增量深化**而非重复实现——经与 main 实况逐项对照，验收 1/2/4 的承载
面已在位，真实缺口在两处：

1. **验收 3「环检测：A→B→A 报 typed 错误不 panic」**——现状环走
   `effective_format` 是静默 visited 截断（读入时 `audit_chains` 登记
   `BrokenReference` 警告，但解析 API 无 typed 错误路径可上抛）；

   与链深），**零个**「继承来的有效字号/字体/缩进」断言。

  四种形态）。

**实现**（分支 `feat/267-style-inheritance`，基于 main `c4baff9`）：

- `StyleChainError`（pub enum）：`UnknownStyle{id}` /
  `CycleDetected{entry, cycle}`——Display/Error 双实现；环路径闭合
  回重复节点（entry=D 查询 A→B→A 环 → cycle=[A,B]——「谁查询」与
  「环在哪」分离可诊断）；
- `StyleTree::effective_props(id) -> Result<EffectiveFormat, StyleChainError>`
  （typed 严格面）：有序路径上溯（Vec 保序 + HashSet 判重），环 →
  `Err(CycleDetected)`（不 panic、不静默截断）、未知 id →
  `Err(UnknownStyle)`、悬空 basedOn → **优雅降级 `Ok`**（以可见链
  合并——验收 4 语义，与 s1-t1 截断行为一致）；合并序与宽松面
  同构（docDefaults 铺底 → 链基底→派生逐层 Some 覆盖，复用
  merge_run/merge_para——两面零分叉）；
- **宽松面 `effective_format` 行为零改动**（s1-t1 语义：环截断 +
  读入警告）——两面互补共存，文档以对照表钉定分界，消费方按
  「要诊断还是要尽力渲染」选面；
- 解析层/写面/既有公开面零改动（`StyleRef`/`read_docx_styles` 系
  列/define_style 均不动——验收 1 的承载面 s1-t1 已交付，本条
  不重复造）。
