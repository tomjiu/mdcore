# #280：wasm 桥双税——apply_ops 整树 clone + word_count 轮询无守卫（2026-11-06，P2 / 审计 P1-19/P1-25）

**背景**（两现象，同一 issue）：

- **P1-19**：`apply_ops` 每事务 `self.tree.clone()` 整树深拷贝（slots
  arena + id_index）——每键 O(全树)；undo/redo 走 `apply_raw_batch`
  同款整树 clone（每次撤销 = 再一次全树克隆）；重放（`from_jsonl`）
  逐记录同款。10MB 文档 wasm 425MB 高水位根因（phase1 登记未治理）。
- **P1-25**：状态栏 `setInterval(refresh, 500)` 无条件调
  `core.word_count_json()`（每块 Rope→String 物化）+ `blocks_count()`
  ——空闲态每秒 2 次全文档扫描 + 分配 churn，无 revision 守卫。

**实现**（分支 `fix/280-wasm-bridge-double-tax`，基于 main `90090d4`）：

- **① 受影响面备份**（`crates/mdcore/src/lib.rs`——审计 notes/11
  方案 B 原样落地）：新 `TxBackup` 分档枚举——
  - `TextNodes`：**全部 op ∈ {ReplaceText, SetMark}**（99% 击键 =
    单块 ReplaceText）只备份逐目标节点 `(text, attrs, marks)` 三元组
    （同节点首现去重；路径解析失败 = apply 同 BadPath 无变更面不备份），
    回滚 = 三元组回写；
  - `Full`：任一结构 op / System / adopt / 重放结构面 → 整树备份
    （回滚面与既有完全一致——零语义风险，方案 B 的设计前提）；
  - 窄档语义安全：两 op 均**先验证后变更**（BadRange 先于任何变更）、
    只变更 text/marks（ReplaceText 经 adjust_marks 联动 marks）、
    slots/id_index/parent/children 零触碰 → NodeId 事务内恒有效、
    路径解析恒定；
  - 三处 clone 点全换：`apply_ops`（每键）/ `apply_raw_batch`
    （undo/redo——文本事务的逆组同 text-class 走窄档）/ `from_jsonl`
    重放（逐记录）；
- **② revision 守卫**（`web/src/main.ts` 状态栏）：`countedRev` 守卫
  ——revision 未变 → 沿用上次文本零重算（首次 tick 必算：初值 -2 与
  0 基隔离）；undo/redo/system 同经 revision 变更触发重算（核单一
  变更入口保证 revision 恰反映内容）——phase2 已锄定的 3 行修法。
