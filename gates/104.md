# #104：LOK worker Windows 消息驱动——message-only window 替代 unipoll（2026-11-11，Agent-ww4y）

## 背景

#69 Windows 实测（LO 26.8.2.2）：内核加载面已修（PR #103 合入，
mergedlo.dll 加载成功、ready 帧正常）后，worker ready 收到请求帧**无应答**，
`bye(run-loop-returned)` 进程退出。Lead 根因定案（#69 评论 2026-11-10
08:37）：LO Windows 版 `run_loop` 要求调用线程**先持有 message-only
window**——无窗口时 runLoop 立即返回；ElyOffice
`crates/ely-lok/src/worker/messages.rs`（Apache-2.0）同款架构实证：先
`window()` 再 `run_loop`，Windows 上 runLoop 阻塞泵消息不返回。本 issue
据此只换 worker 主循环驱动层，协议/分发/client 零改动。

## 实现（crates/lok/src/worker.rs，#104 任务四条逐条）

1. **RegisterClassW + CreateWindowExW(HWND_MESSAGE)**：`window_create()`
   手写 `WNDCLASSW` repr(C)（零新依赖，本仓 FFI 风格）；
   `WM_APP+1`=ASK（lparam=`Box<Vec<u8>>` 帧指针）/`WM_APP+2`=CLOSED
   （wparam=退出码 0=EOF / 2=帧读失败——语义对齐 unipoll `Note::Closed`）。
2. **reader 线程 stdin 帧 → PostMessageW**：帧所有权 Box 独占移交，
   投递失败即回收防泄漏 + `hard_exit(2)` 如实报协议失败；EOF →
   PostMessageW(CLOSED)。HWND 以 usize 携带跨线程（Send 纪律）。
3. **WndProc 复用现有分发**：ASK → `handle_frame`（与 unipoll 同一条
   JSON 解析→dispatch→answer_or_oversize 链，**平台零分叉**）；
   CLOSED → `loop_exit`（与 unipoll 同因同码）。主循环上下文经
   `WND_CTX: AtomicPtr<LoopCtx>` 静态指针（泵开始前必已就位，
   PostMessage 只入队不直调——无竞态）。
4. **runLoop(空 poll, 空 wake)**：`messages_poll`/`messages_wake` 空实现
   ——unipoll 契约（`SAL_LOK_OPTIONS=unipoll`，env_hygiene 两侧已设）
   要求 hooks 非空，Windows 消息循环从不调用（ElyOffice messages.rs:41-45
   原注释："Unipoll needs hooks; the Windows loop never calls them"）。

**平台区分**（用户要求重点）：

- `unipoll_loop` / `unipoll_poll` / `unipoll_wake` / `WAKE_TX` / `Note`
  全部 `#[cfg(not(windows))]` 收窄；`LoopCtx.rx` 字段同收窄（消息路径
  不用通道）。Linux 路径逐字节不变（diff 仅 cfg 属性与文档）。
- Windows 全段 `#[cfg(windows)]`：messages_loop / window_create /
  messages_wndproc / messages_poll / messages_wake / WND_CTX / WNDCLASSW。
- 窗口创建失败（RegisterClassW/CreateWindowExW 0 返回）：bye 事件如实
  报因 `window-create-failed` + `hard_exit(3)`（新退出码，注释登记）。
