# #232：mdc-pdf 表格结构化提取（2026-11-06，R9·P1 / 研究仓 #252·#251 证据）

**背景**：真实政采评分表 PDF 线性化后列交错，研究仓 #252 被迫写 785 行
scoring_table 专路仍 16 锚点仅 4 命中——结构化提取在引擎侧一次做对。

**实现**（分支 feat/pdf-table-extract）：
- `crates/pdf/src/table.rs`（常开模块，纯函数零引擎依赖——与会话注入
  几何同哲学）：PositionedChar（字符+包围盒+字号）→ 行带聚类（垂直
  中心容差 0.5×中位字高）→ 行内 x 间隙切格（max(4pt, 0.9×中位字高)）
  → 连续多格行成表（单格行[标题/段落]不入表；垂直断档 > 3×中位字高
  拆表）→ 列左缘锚 1D 聚类（max(6pt, 0.2×中位格宽)）+ **幽灵锚防御**
  （跨列格左缘不成锚——合并格中途起笔不产生幻影列）→ 单元格
  {文本, col_index, col_span, 包围盒}——行列可重建；
- `engine_pdfium.rs::positioned_chars`（feature engine-pdfium）：
  逐字符 loose_bounds + 实际字号——位置层；lopdf 位置层（内容流字体
  度量解码重）不在 v1，登记；
- 夹具 `table_grid.pdf`（`gen_table_fixture.py`——合成评分表 4 列 ×
  6 行：表头 + 4 数据 + 合计行合并格 col_span=2；页首标题/表后段落
  单格行 = 不入表锚；生成器头注即金标准）；
- `tests/pdfn_table_extract.rs`：算法层 4（网格全量重建 / 合并格中途
  起笔跨锚 / 单格行排除 / 空与退化输入）+ pdfium e2e 2（金标准对照 +
  位置层页界防御）。

**实施发现（两坑一防，如实登记）**：① 行带字符必须按左缘排序——
聚类按 center_y 进栈而切分以左序游走，不排序时真实 pdfium **阅读序**
字符流切出交错垃圾格（合成注入序碰巧左序，纯函数测试不暴露，e2e 才
暴露）；② 合并格中途起笔的左缘自成锚 → 幽灵列使 col_index 右移——
跨列格左缘不参与锚定的防御规则；③ 表 bbox 纵向界须在 block 消费前
捕获（所有权）。

**验证面**：本地（Linux，pdfium chromium/8086 linux-x64 @ bin/lib）——
`cargo test -p mdc-pdf --features engine-lopdf,engine-pdfium` **252 ok /
0 failed**（含新增 6：金标准 e2e 行/列/文本/列序/合并格逐项对照）；
clippy 0 警告；fmt 0 diff；scan 命中仅 main 基线既有 A3 两行（修复在
#237——本分支基于 main 继承；自增面零命中实证）；CI 三门禁（check /
engine tests[含 pdfium 面] / mang-shell）。

**登记边界**：对齐式表格（含无框线）——矢量线框（ruling lines）检测
不在 v1；列锚左缘聚类：左对齐列精确，居中/右对齐列 col_index 可能
偏移；跨页续接/嵌套表/旋转页/单元格内软换行不在 v1（软换行拆独立行
处理，模块文档登记）；研究仓真实评分表语料只读引入未做（issue「可
只读引入」为可选）——合成金标准先行，真实语料验证随消费方接入
（mang-shell/web 表格读面）按需补。
