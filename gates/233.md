# #233：office-io zip-exotica 防线（2026-11-06，R10·P2 / 研究仓 audit INTEG-002 · commit 1e0bc9d）

**背景**：研究仓 B4（50e6332）按「容器安全收敛引擎侧」原则删除自有
zip 防线（guard.rs 943 行，含 18 项 zip 面负向测试），audit INTEG-002
证实引擎侧等价防线缺位：EOCD 守恒族（尾垃圾/影子 EOCD/字段分歧/
zip64 重复）与压缩比门两仓皆无；且研究仓防线基于 zip 4.6.1 语义，引擎
用 zip 8.6.0——行为差异零验证。

**取证（只读）**：五族样本生成器全部从研究仓 git 历史取回
（guard.rs @ 50e6332^ + baseline_run.py）；python 重建件 sha256 交叉
验证（03-duplicate-entries 逐字节一致 f71b9956…306dd1d）。

**实现**（分支 fix/zip-exotica-defense）：
- **EOCD 守恒门**（`io.rs::eocd_conservation`——研究仓 M1.6 镜像的
  轻量移植：只比计数不重建目录）：宽松回扫（容忍尾垃圾/影子
  comment 越 EOF 跳过）+ zip64 链（locator→z64 记录真实计数）→
  声明计数 vs crate 实际条目数；分歧（EOCD 双字段互异）或守恒破坏
  （声明≠实际）→ 拒（fail-closed：候选全不可验证 = 拒非跳过）。
  接线：docx 读面（read_bytes_gated，path/bytes 四入口漏斗）+ 编辑面
  （DocxEditor::open_with_policy）+ xlsx 字节入口
  （read_book_from_bytes_with_options）；xlsx 路径入口保惰性 Seek
  无全量分配设计不接（登记：路径面为桌面本地消费，敌意主面在
  bytes 入口）；
- **zip 8.6 语义钉定**（实测）：解析层 IndexMap 吸收物理同名条目
  ——`len()`/`by_index` 视野看不到重复（重复名门对 CDFH 同名对
  失效，守恒门因此必要——by_index 查重保留为纵深）；尾垃圾/
  影子/分歧/zip64-dup 全部「打开成功」穿过 by_index 面（守恒门
  全数拦截）；
- **压缩比观察门**（警告口径不拒）：`LIMIT_COMPRESS_RATIO=100` ×
  `WarningKind::HighCompressionRatio`（verify_pass 单点，两模式恒
  登记不静默）；**硬拒有实证误报面**（研究仓 engine-probe s7b：
  合法 149:1 高压缩比件被引擎正常接受——6000 段全解析），膨胀上界
  已由门 0/1/2 钉死（输入字节/声明总量/谎言头 CountingReader）；
  乘法判据（研究仓 R5 P-2 整数除法截断漏洞教训：100,999 拒/
  100,000 放行边界对移植）；wasm 警告映射 `high_compression_ratio`
  /severity `info`（docx+xlsx 双面）；
- `tests/zip_exotica.rs`（8 测试）：五族负向（S1 尾垃圾三档差分
  [65,535/65,536/65,600——65,536 为 zip 4.6.1 旧守卫窗实测绕过
  阈值，引擎门与窗口无关三档一致] / S2 影子 EOCD / S3 字段分歧
  双向 / S4 zip64-dup + **合法 zip64 正向对照[不误拒]** / S5 炸弹
  typed 终态 + 警告可见性 + 乘法边界对 / S6 研究仓在库敌意件
  03-duplicate-entries）+ 非 zip 垃圾正控；构造辅助逐字移植自
  研究仓（write_zip/incompressible/patch_central_name/make_zip64）；
- **契约变更**：docx_roundtrip 的「重复条目 last wins」容忍语义
  （docx-r1 时代钉定）升级为守恒拒绝——测试改写
  `image_inventory_duplicate_zip_entries_rejected_by_conservation`
  （行为变更依据 = issue #233 / audit INTEG-002 的更晚用户裁决）。
