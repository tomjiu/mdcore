# #279：pdf worker 换代上限——敌意反复超时的资源硬上界（2026-11-06，P2 / 审计 P1-12）

**背景**：`worker.rs` 换代时旧代 join 句柄弃置（detach）。注释自述
「退出即自然回收」——但**永挂的 C 调用（pdfium 内部长阻塞）不返回则
线程永不退出**；通道 drop 只在作业完成后才生效。反复敌意超时 → 每次
换代产生一个永挂线程 + 一个引擎实例（字节快照重开，S4.4）——线程与
快照无上界累积（审计 P1-12）。

**实现**（分支 `fix/279-worker-generation-cap`，基于 main `90090d4`）：

- **换代上限 `pub const MAX_GENERATIONS = 16`**（一生含首代至多 16
  代）：敌意反复超时的线程/引擎实例硬上界。取值权衡：合法场景看门狗
  （默认预算 20s）极少触发，一生 16 次超预算已属病态；敌意场景上界
  = 16 永挂线程 + 16 引擎实例（有界可存活）。达上限 → **退役态**：
  - 不再派生新代；在飞作业（含重放中的）**合成 `WorkerReply::Timeout`**
    （❸弃置语义——等待面不悬挂；复用既有变体，**协议面零变化**，
    CONTRACT §6 无需升版）；
  - 后续 `submit` 即刻登记 + 合成 `Timeout`（**先 stash 后落账**——
    in_flight 保留至回执送达由 accept 逐个 validate+prune；先清则
    合成回执被验收面当无效丢弃，「至多一条」退化为零条——既有防御
    路径的隐藏陷阱在可达路径上的规避）；
  - 通道换哑元断连（recv 面死亡可观测、send 静默失败——与工厂
    panic 死亡同款观测语义）；
  - 当前代句柄转入 `retired`（永挂不 join——敌意 C 调用不得悬挂
    drop，与旧代弃置同纪律）；
- **退役句柄跟踪式弃置**（detach 升级）：旧代句柄入 `retired`，
  finished 即收割（join 回收——零阻塞）、永挂计数在案；新增观测面
  `pub fn retired_alive() -> usize`（上界恒 ≤ `MAX_GENERATIONS`——
  换代上限的机械保证；健康路径恒归零）与 `pub fn is_exhausted() ->
  bool`（宿主可提示「渲染工人退役，重启会话可复位」）；
- **drop 不悬挂不变量保持**：退役态当前代已入 `retired`（不 join
  永挂线程）；sweep 全程零阻塞（join 已结束线程立即返回）。

**需要 Lead 裁定的**（非本条范围，登记不动）：

- **永挂线程的进程级回收**：Rust 无法安全杀线程；心跳检测也只能
  观测不能回收。根治 = 每代渲染线程改子进程隔离（架构级变更，
  影响 S4 边界与部署面）——v0 以计数上界兜底（有界泄漏 + 可观测
  + 宿主可复位），架构裁定留 Lead。

**测试证据**（本机 Linux 实测，`cargo 1.99.0`）：

- `pdfc_cache_worker.rs` 新增 24 号锁
  `worker_generation_cap_bounds_stuck_threads`（HangMock 永挂 rig
  ——模拟不可中断敌意 C 调用，释放旗标收尾；**每代都挂** = 最坏
  敌意形态）：
  - 20 次敌意提交（超 16 上限）逐作业 `Timeout` 回执（至多一条
    合同保持）；
  - `is_exhausted()` == true / `generation()` 封顶 `MAX_GENERATIONS-1`
    （代数硬上界）；
  - 退役态 submit **即刻**合成 Timeout（实测 < 2s 断言——修复前
    此路径送死通道永无回执，等待面必悬挂）；收报断连 None（死亡
    可观测）；
  - `retired_alive()` == `MAX_GENERATIONS`（悬挂态精确上界——有界
    泄漏的直接量度）；
  - 释放旗标 → `retired_alive()` → 0（收割回收证明——跟踪式弃置
    的观测面价值）；drop 实测 < 5s 不悬挂；
- `cargo test -p mdc-pdf --features engine-lopdf`：**198 passed /
  0 failed**（worker 面 24/24——既有 23 锁含 19-23 号看门狗族零
  回归：单次换代/重放序/裸工人/工厂 panic 双路径全兼容）；
- `cargo check --workspace --all-targets --exclude mdshell-native`
  过（排除口径 = CI windows-check 同款；本条不触 mang-shell）；
  `cargo check -p mdcore-wasm --target wasm32-unknown-unknown` 过；
- `cargo fmt --check` 0 diff / clippy 零新增 warning。

**消费面影响**：`RenderWorker::watchdog` 当前为能力面（PDF-e 实装
在 worker.rs 自身，无生产装配点——render.rs 只冻结抽象面）——上限
语义对既有消费方（测试面）零破坏；未来装配点的退役态处置语义已在
模块文档 + `is_exhausted` 观测面就位。

**CI 面**：windows-test 跑 `cargo test -p mdc-pdf --features
engine-lopdf,engine-pdfium`——新测试纯 Rust 零外部依赖（无引擎/
语料/工具），Windows 可全量运行（~1.4s，无线程数敏感断言）。
