# #281：mang-shell 状态栏每帧 I/O 与字数物化残项首批（2026-11-06，P2 / 审计 P1-17·P2-31 R-e/R-f）

**背景**（phase2 笔记 22 R 系残项群的首批收口）：

- **R-e**：状态栏随 ShellApp 每次重渲被调（gpui 祖先标脏机制——每键/
  每拖拽 move 都整树重渲）：`status_bar.rs:79` md 态 `std::fs::read`
  **整文件读盘**（编码/EOL 探测 #188 面）——大文件持续磁盘 churn，
  残项中唯一 I/O 类、量级最重；同族 `.git/HEAD` 每帧重读。
- **R-f**：字数标签每帧 2× 全文物化——`char_label →
  char_count() → to_plain_text().chars().count()`（O(doc) 分配），
  status_bar.rs:112 + panels.rs:214 双消费点。

**实现**（分支 `fix/281-statusbar-io-cache`，基于 main `90090d4`）：

- **R-e → mtime+size 失效缓存**（`status_info.rs`——审计钉定方案）：
  - `detect_encoding_eol_cached(path)`：stat 命中（mtime+size 相等）
    直接复用探测结果，零读盘；未命中/失效恰读一次重新探测。同
    mtime 同 size 但内容已变（同秒重写同长文件）为已知边界（在档）
    ——状态标签滞后一帧级探测语义；
  - `git_branch_at_cached(root)`：HEAD mtime 失效（checkout 更新
    HEAD mtime → 恰失效一次）；HEAD 解析提取 `resolve_head_path`
    （worktree `.git` 文件形态共用）；`.git` 目录上溯 walk 保留每帧
    执行（纯 stat 无数据传输，量级可忽略）；
  - `status_bar.rs` 两消费点换缓存版；
- **R-f → Editor 层 revision 守卫缓存**（`editor/mod.rs`）：
  `char_count_cache: RefCell<(u64, usize)>`（键 = Buffer revision——
  每变更事务 +1：replace_range/replace_batch/undo/redo；mark_saved
  不算）。`Editor::char_count()` 惰性守卫：键变首读重算，纯光标
  移动/纯重渲零物化。RefCell 惰性设计（非 refresh_caches 挂钩）：
  与 after_edit 收尾路径**零耦合**——任何变更入口（含 RPC/批替换）
  都经 Buffer revision 自动正确。状态栏/属性面板/RPC get_state 三
  消费面一并受益；`Buffer::char_count` 保持纯函数不动。

**测试证据**（本机 Linux 实测，mang-shell `cargo test --lib`）：

- **460 passed / 0 failed**（基线 457 + 新 3）；
- `encoding_eol_cache_hits_and_invalidates`——READ_COUNT 观测面
  （真实 `fs::read` 计数）：未命中恰读一次 → 五次重渲**零读盘** →
  文件变更（size 变）恰失效重读一次 + 新内容探测正确；
- `git_branch_cache_invalidates_on_checkout`——命中 + checkout
  （HEAD 重写）失效读新分支；
- `char_count_cache_follows_revision`（gpui::test 真实编辑器）——
  初读填充（键对齐 revision）/未变更复读键值对不动（纯光标移动
  零重算的结构性保证）/变更事务后键值恰 +1 跟进/`char_label`
  行为面含最新计数；
- fmt：新代码净（`rustfmt --check` 仅剩同文件 3 处既有漂移——
  406/414/477，非本条引入不动）；clippy 零新增。
