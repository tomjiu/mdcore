# #277：stamp.rs 写面安全门 + 桌面读路径 S2/S6 接线（2026-11-06，P2 / 审计 P1-11）

**背景**：审计 P1-11 指出 `crates/pdf/src/stamp.rs` 是全 PDF 写面唯一
裸奔入口——零 `is_encrypted`/S5 加密门/S3 输入门命中。对加密档盖章会
**静默损坏**：仍加密态 lopdf 以未解密形态装载、对象图不解析，保存出的
产物既非合法修订也非原档语义；曾加密态（空口令自动解密）则静默剥离
加密层。对照：#227（R3）已为 forms 面补上同款保护，stamp 面未跟进；
桌面读路径（mang-shell `pdf_doc::load`）也不接 S2/S6 `open_scan`
（web 面有、桌面没有的双标）。

**实现**（分支 `fix/277-stamp-encrypted-gate`，基于 main `90090d4`）：

- **stamp 双门**（`stamp_image` → `stamp_image_with_limits` 双入口，
  与 `forms::read/read_with_limits` 同款纪律）：
  - **S3-L7 输入门**先于一切解析（`Limits::check_open_input_bytes`
    ——open 家族入口统一，与 `open_scan`/`PdfiumEngine::open`/
    `LopdfWriter::from_bytes` 同序）；超限 → 新变体
    `StampError::TooLarge`（typed 拒）；
  - **S5 加密双拒**（lopdf 装载后）：`is_encrypted() ||
    was_encrypted()`——判定取 `writer_lopdf` 强形态而非 forms 单拒：
    文件本体是加密档即拒（v0 S5 = 加密档零写）；曾加密态保存 =
    静默剥离加密层（安全降级），同样拒 → `StampError::Encrypted`；
- **桌面读路径接线**（mang-shell `pdf_doc.rs`，此前零 `open_scan`
  命中）：
  - `load_from_bytes` 在引擎打开前跑 `open_scan`（S2 八族 + S6 表单
    探针 + S5 旗标）——**S2.4 只读告警语义：不阻断打开**（桌面视图
    只读零执行面）；扫描失败不阻断（lopdf 与 pdfium 是独立解析器，
    装载判定权在引擎）；
  - 评估转全局提示行落行模型首行区（与扫描件提示同通道，先于它
    ——安全语义优先）：`security_notice_lines`（S2 命中计数 + 族名
    去重中文呈现 + S6 字段计数）经 `PdfRaw.security_notices` 注入
    `convert`；页表/书签锚点随提示行数整体平移（构造性保持）；
  - **仍加密态诊断前置**：扫描见加密旗 + 引擎打开失败 → 错误面附
    「文档处于加密态」提示（诚实对冲绑定失败共存可能）；
- 错误窄面不变（不污染 `CommandError`），`stamp_image` 签名零改动
  （既有调用方/测试零破坏）。

**测试证据**（本机 Linux 实测，`cargo 1.99.0`；引擎面借
`MDC_PDFIUM_LIB` 指向 pypdfium2 内置 libpdfium 真跑）：

- `pdfh_stamp.rs` 新增 3 锁（加密夹具 lopdf V1 RC4 现场构造——
  pdfe_security 5 号同款，零仓外依赖）：
  - `still_encrypted_pdf_stamp_is_rejected`——仍加密态（口令不可得）
    → `Err(Encrypted)`（原始事故形态锁）；
  - `was_encrypted_pdf_stamp_is_rejected`——曾加密态（空口令自动
    解密，夹具前置自证 `is_encrypted=false && was_encrypted=true`
    防漂移退化为单拒锁）→ 同拒（双拒锁）；
  - `oversized_input_is_rejected_before_parsing`——S3-L7 注入小限额
    确定性触发 + 等长边界放行（HardReject 语义）；
  - `cargo test -p mdc-pdf --features engine-lopdf`：全量绿
    （pdfh_stamp 11/11，含既有 8 锁零回归）；
- mang-shell `pdf_doc.rs` 内嵌新增 2 锁（纯函数零引擎依赖）：
  - `security_notice_lines_format_and_dedup`——命中计数/族名去重/
    S6 计数/良性档零提示（误报 = 告警面失效）；
  - `security_notices_land_first_and_shift_anchors`——提示行落位
    最首 + 页表/书签锚点平移不漂 + Quote 整行 span；
- mang-shell `render_170_pdf.rs` 新增 1 把 e2e（引擎门控，无
  libpdfium 环境 SKIP 横幅——同 ①号 Phase B 口径）：
  `dangerous_pdf_opens_with_security_notice_when_engine_available`
  ——现场构造 catalog `/OpenAction` 敌意件（Phase A 独立对账防构造
  漂移）→ 打开成功 + 首行【安全提示】+ 族名指认 + 只读语义声明 +
  S6 不误报 + 页表照常（不阻断）；
- `cargo test --lib`（mang-shell）：**459 passed / 0 failed**
  （基线 457 + 新增 2）；render_170_pdf 4/4、render_fidelity 8/8
  （含引擎面真跑——smoke.pdf 良性件零告警零行为变化）；
- `cargo fmt --check` 0 diff（两 crate）；`cargo clippy` 零新增
  warning（mdc-pdf 既有 `TableCell` unused import 为 main 基线，
  stash 对照实证）。

**环境边界（诚实登记）**：

- 本沙箱缺 `libxkbcommon-x11` 系统链接库 → mang-shell **bin 靶**
  链接失败（GPUI x11 feature 面要求）——环境限制非本条缺陷（本条
  零改动构建配置）；lib/test 靶不受影响全量真跑。CI（Windows）
  有完整系统库，bin 正常；
- 引擎面测试经 `MDC_PDFIUM_LIB` 指向 pypdfium2 内置 libpdfium
  （沙箱无仓内取件位）——版本与 pin 面的兼容性由测试通过本身
  背书；CI 用仓内 `bin/lib/pdfium.dll` 正常跑。

**CI 面**：windows-test 跑 `cargo test -p mdc-pdf --features
engine-lopdf,engine-pdfium` + mang-shell 自身门禁——新增测试零
外部工具依赖（无 poppler/soffice），敌意/加密夹具全部现场构造，
无环境门需求（引擎门控自恰：无 libpdfium SKIP，有则真跑）。
